# セルフレビュー

1. `git diff main...HEAD` で差分を読む。
2. 下の観点で確認する。
3. 問題を重要度順に報告する。場所は `ファイル:行` で示す。
4. 重大な問題は直して、`/verify` をもう一度実行する。

## 観点

- **目的**：依頼や仕様（`docs/specs/`）と合っているか。頼まれていない変更が混ざっていないか。
- **テスト**：変えた振る舞いにテストがあるか。失敗するケースも試しているか。
- **エラー**：エラーを握りつぶしていないか。メッセージで原因がわかるか。
- **安全**：秘密情報、外部入力の扱い、破壊的な操作に問題がないか。
- **単純さ**：不要な抽象化、使われていないコード、重複がないか。

## リスクが高い変更

認証・決済・個人データに関わる変更は、その旨を報告の先頭に書く。人間のレビューが必須。
