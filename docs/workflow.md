# 開発の流れ

エージェントにコードを書かせ、人間は仕様・環境・検証を設計する。
この文書は、人間とエージェントの両方が読む。

## 基本のループ

1. **探索**：関係するコードを読む。まだ書かない。
2. **計画**：変更内容と検証方法を書き出す。人間が確認する。
3. **実装**：計画どおりに小さく変更する。
4. **検証**：`make check` を通す。振る舞いは実際に動かして確認する。

小さな修正（誤字、1行の変更）は計画を省いてよい。

## テストを先に書く

振る舞いを変えるときの手順。

1. テストを書く。
2. 失敗することを確認する。
3. テストをコミットする。
4. テストを変えずに、通るまで実装する。

## 仕様

- 新しい機能は `docs/specs/TEMPLATE.md` をコピーして書く。短くてよい。
- 受け入れ基準は、できるだけテストで表す。
- 仕様は実装に合わせて更新する。古い仕様は残さない。
- 小さなバグ修正に仕様は書かない。

## リスクに応じた監督

| リスク | 例 | 進め方 |
|---|---|---|
| 低 | 使い捨てのスクリプト、試作 | エージェントに任せてよい。本番には入れない |
| 中 | 通常の機能 | 計画を確認し、差分を人間がレビューする |
| 高 | 認証・決済・個人データ・破壊的な操作 | 仕様を先に確定する。テストを厚くする。複数人でレビューする |

承認は形だけにしない。差分を読み、説明できる状態でマージする。

## レビュー

1. エージェントが `/self-review` で自分の差分を確認する。
2. CI が `make check` と AI レビューを実行する。
3. 人間が最終承認する。設計、仕様との一致、安全性を見る。

## コンテキスト

- 関係のないタスクに移る前に、会話をクリアする。
- 長い作業では、進み具合をファイルに書き出す。
- `AGENTS.md` は短く保つ。詳細は `docs/` や Skills に置く。

## エージェントがつまずいたら

同じ失敗を繰り返させない。足りないものをリポジトリに戻す。

- 知識が足りない → `AGENTS.md` の「落とし穴」に1行足す。
- 手順が足りない → `.claude/skills/` に Skill を足す。
- 検証が足りない → テストや lint ルールを足す。

## 並列実行

- git worktree やクラウド実行で並列化できる。
- 並列数は、人間がレビューできる量までにする。

## 安全

- 権限は `.claude/settings.json` で制御する。`AGENTS.md` に書いても強制されない。
- 権限確認を省いて動かすのは、コンテナや VM の中だけにする。
- MCP サーバーやプラグインは、出所が確かなものだけ使う。
- 重要なモジュールには、ミューテーションテスト（`make mutation`）でテストの質を確かめる。
